= Builder poudriere — modèle B — Plan d'implémentation
:toc: left
:icons: font
:status: PLAN — décisions actées le 16 juin 2026, prêt à exécuter à l'arrivée de la box

[abstract]
Implémentation concrète du dépôt `pkg` privé signé (cf.
`poudriere-repo-architecture.adoc`), en **modèle B (dépôt complet)**, sur une
**box FreeBSD dédiée**, servi **sur le vRack**. Ce document décrit le QUOI et le
COMMENT exécutables ; l'architecture/justification est dans le doc parent.

== 0. Décisions actées (architecture §8, tranchées)

[cols="1,3"]
|===
| Décision | Choix

| Emplacement builder | **Box dédiée** (pas une jail sur la prod) → isolation totale, aucun toolchain de build sur les serveurs applicatifs.
| Modèle | **A — overlay** (révision 16 juin) : poudriere ne construit QUE ce qui a disparu de l'officiel (EOL) ou qu'on doit personnaliser. Tout le reste vient des paquets OFFICIELS. Les clients activent l'officiel + `quimeo` (priorité quimeo sur ces quelques paquets). Rebuilds courts. On abandonne le « tout-poudriere » initial.
| Service du dépôt | **vRack `pn-1049829`** (PAS headscale — pivot bastion vRack). nginx sur l'IP vRack du builder.
| Mesh headscale/tailscale | **CONSERVÉ** dans la build list : les bastions `z` deviennent **serveurs de chiffrement** (déverrouillage des partitions via le mesh — chantier séparé).
| Clé de signature | Stockée dans le **coffre beryl** (`.env.toml.age`), confinée au builder.
| Overlay ports | Nouveau dépôt git **`quimeo-ports`** (société QuimeO).
|===

== 1. Le builder (box dédiée)

* Gamme OVH **avec vRack** (Advance/Rise/Scale ; PAS So-you-Start/Kimsufi).
* **8-16 cœurs**, **32-64 Go** RAM ECC, **2× NVMe** → ZFS **mirror**
  (`bpool`/`zroot` ou un pool dédié `ppool` pour `/usr/local/poudriere`).
* **FreeBSD 15.0 amd64** (ABI = la flotte), bootstrappé par beryl.
* Rattaché à **`pn-1049829`** + IP vRack (recette `vrack-interface`).
* **Résiliable** : pas prod-critique, on peut l'éteindre entre rebuilds.

Provisionnement (flux beryl éprouvé) :

[source,sh]
----
beryl scan <ns-name> --hostname=builder --dns --write   # service_name auto + DNS
beryl vrack builder.quimeo.net --attach                 # dans pn-1049829
beryl bootstrap builder.quimeo.net                      # FreeBSD 15 + ZFS mirror
----

== 2. Mise en place poudriere (recette `poudriere-builder`, à écrire)

. `pkg-install`: `poudriere-devel`, `git`, `nginx`, `ca_root_nss`.
. **Pool/datasets** : poudriere utilise ZFS (`ZPOOL`, `ZROOTFS`). Pointer sur
  le pool du builder (`/usr/local/etc/poudriere.conf`).
. **Jail** : `poudriere jail -c -j fbsd150amd64 -v 15.0-RELEASE -a amd64`.
. **Arbre des ports** : `poudriere ports -c -p default` (+ MAJ régulière).
. **Overlay** `quimeo-ports` (`poudriere -O`) : clone du dépôt git, contient
  nos ports maison (`chruby`, `ruby27-quimeo`, et tout port retiré de l'officiel
  qu'on veut figer — Makefile/distinfo/pkg-plist récupérés de l'historique).
. **Clé de signature** : générée sur le builder, **clé privée lue depuis le
  coffre** (`beryl env`), publique distribuée aux serveurs (fingerprints).
. **`poudriere bulk`** de la build list → dépôt signé sous
  `/usr/local/poudriere/data/packages/fbsd150amd64-default/`.

== 3. Build list (modèle A — overlay : UNIQUEMENT l'EOL/custom)

RÉVISION 16 juin : on ne reconstruit PAS ce qui est déjà dans les paquets
officiels. Le dépôt `quimeo` ne contient QUE ce qui a disparu de l'officiel
ou qu'on doit personnaliser :

[cols="1,3,2"]
|===
| Paquet | Pourquoi (absent/inadéquat dans l'officiel) | Source

| `openssl111` (libssl 1.1.1) | EOL → retiré des ports | overlay (Makefile/distinfo/plist récupérés de l'historique git)
| `ruby27-quimeo` (Ruby 2.7.8) | EOL → retiré des ports ; doit être lié à openssl111 | overlay
| `nginx` `[PASSENGER=on]` | l'officiel ne fournit PAS l'option passenger | `www/nginx` + option (poudriere, modèle cuit — fini le compile runtime/libev)
| `rubygem-passenger` (ruby 2.7) | intégration passenger pour ruby 2.7 | overlay/option
| `chruby` + gems/outils figés | figés ou retirés | overlay au cas par cas
|===

Tout le reste (`bash` `zsh` `git` `tmux` `mariadb` `postgresql` `tailscale`
`headscale` `clamav` `ca_root_nss`…) vient de l'**OFFICIEL**. La liste des
paquets `quimeo` vit dans un fichier poudriere (`bulk -f pkglist`)
**versionné** (git), source de vérité du « custom ».

== 4. Signature (sécurité §2.2 du doc parent)

* Clé **RSA** générée sur le builder ; `PKG_REPO_SIGNING_KEY` dans
  `poudriere.conf`.
* **Privée** : jamais hors du builder ; copie chiffrée dans le coffre beryl
  (sauvegarde/rotation). **Publique** : distribuée comme `fingerprints`.
* Sauvegarde + rotation : à documenter (procédure dédiée).

== 5. Service du dépôt (nginx sur le vRack)

* `nginx` sert `/usr/local/poudriere/data/packages/<jail>-<ports>/` en HTTPS,
  **bind sur l'IP vRack** du builder (pas d'exposition publique — `pf` bloque
  le port public, cf. esprit `sshd-vrack-only`).
* URL côté clients : `https://<ip-vrack-builder>/${ABI}` (ou un nom interne).
* Certificat TLS interne (ou HTTP simple sur le vRack — réseau privé L2).

== 6. Intégration beryl (recettes, à écrire)

. **Primitive `pkg-repo`** : pose `/usr/local/etc/pkg/repos/aloli.conf` +
  la clé publique dans `fingerprints/aloli`. Idempotente. (cf. doc parent §6)
. **Recette `pkg-repo-aloli`** : enrôle un serveur (priorité > officiel).
. **Bascule** : `chruby`/`ruby27-aloli` → `pkg-install` ; **retrait de
  `make-install`** (ou conservé en secours rarissime).
. Recette `poudriere-builder` (§2) : beryl gère aussi l'infra de build.

== 7. Rebuild (cadence + déclencheurs)

* `cron` sur le builder : MAJ ports + `poudriere bulk` + regen dépôt (hebdo).
* Déclencheur **avis de sécurité FreeBSD** (à câbler).
* `ccache` activé (`USE_TMPFS`, `CCACHE_DIR`) → rebuilds rapides.

== 8. Phasage d'exécution

[cols="1,4"]
|===
| Étape | Action

| 1 | Commander la box (gamme vRack, 8-16c/32-64Go/2×NVMe). Créer le dépôt git `quimeo-ports`.
| 2 | `beryl scan/vrack/bootstrap` → FreeBSD 15 + ZFS, dans pn-1049829.
| 3 | Recette `poudriere-builder` : poudriere + jail 15.0 + overlay + clé de signature.
| 4 | `poudriere bulk` de la build list → 1er build (≈ quelques heures) → dépôt signé.
| 5 | nginx sur le vRack → dépôt joignable par les serveurs.
| 6 | Primitive `pkg-repo` + recette `pkg-repo-aloli` ; enrôler obi/wan/ben/z.
| 7 | Bascule `chruby`/`ruby27-aloli` → `pkg-install` ; retrait `make-install`.
| 8 | Cron de rebuild + supervision.
|===

== 9. Hors périmètre / chantiers liés

* **Chiffrement zroot** (obi/wan/ben) + **z = serveurs Tang/déchiffrement** via
  le mesh : chantier SÉPARÉ (cf. `zpool-encryption-architecture.adoc`,
  `beryl tang-enroll`/`unlock`). Justifie qu'on garde `headscale`/`tailscale`
  dans la build list.
